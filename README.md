# MushGuard

A Django web app for mushroom identification, reporting and mapping.

- **Database:** Supabase Postgres
- **Uploads:** Supabase Storage (S3-compatible API, via `django-storages`)
- **Hosting:** Render (gunicorn + WhiteNoise for static files)
- **Email:** Brevo API (falls back to printing emails in the console)

## Local development

```bash
python -m venv venv
venv\Scripts\activate          # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env         # macOS/Linux: cp .env.example .env
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

With `DATABASE_URL` and the Supabase Storage variables left unset, the app uses
SQLite and stores uploads in `media/`.

## Supabase setup

1. **Create a project** at supabase.com. Pick a region close to your Render
   service (e.g. Southeast Asia / Singapore).
2. **Database URL:** Project → **Connect** → **Session pooler** → copy the URI
   and put your database password in it. It looks like
   `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`.
   Use the pooler, not the direct `db.<ref>.supabase.co` host: the direct host
   is IPv6-only and Render can't reach it.
3. **Storage bucket:** Storage → **New bucket** → name it `media` and mark it
   **Public** (images are shown on the public map).
4. **S3 keys:** Project Settings → **Storage** → **S3 Connection**. Note the
   region, then create an access key and copy its ID and secret.

## Deploying to Render

1. Push the repo to GitHub and create a **Blueprint** on Render from
   `render.yaml` (or a Web Service with build command `bash build.sh` and
   start command `bash start.sh`).
2. In the Render dashboard, set the secret environment variables:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | Supabase session pooler URI |
   | `SUPABASE_PROJECT_REF` | the `<ref>` in `https://<ref>.supabase.co` |
   | `SUPABASE_S3_REGION` | region shown on the S3 Connection page |
   | `SUPABASE_S3_ACCESS_KEY_ID` / `SUPABASE_S3_SECRET_ACCESS_KEY` | S3 access key |
   | `BREVO_API_KEY` | Brevo API key |
   | `BREVO_SENDER_EMAIL` | a sender address verified in Brevo |

   `SECRET_KEY` is generated by Render. If your URL isn't
   `mushguard.onrender.com`, it's still allowed automatically through
   `RENDER_EXTERNAL_HOSTNAME`.
3. Deploy. Migrations run on every start.
4. Create the admin account once, from the Render **Shell**:
   ```bash
   python manage.py createsuperuser
   ```

### Moving existing data to Supabase

If you have data in an old database, export it with `DATABASE_URL` pointing at
the old database, then import it with `DATABASE_URL` pointing at Supabase:

```bash
python manage.py dumpdata --natural-foreign --natural-primary -e contenttypes -e auth.permission -e admin.logentry -e sessions -o data.json
python manage.py migrate
python manage.py loaddata data.json
```

To copy the images in the local `media/` folder into the Supabase bucket (with
the Supabase Storage variables set):

```bash
python manage.py upload_media
```
